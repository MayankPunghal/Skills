# generate-reference — exhaustive, anchored reference pages

Everything enumerable is generated, never hand-typed: that is what makes "nothing missed" true and checkable. Narrative pages then link into these entries with tags.

## Steps

1. Pick adapters from the survey's "Suggested adapters" and set them in `codebase-docs.json`:

   ```json
   "adapters": ["generic-graph", "generic-deps", "generic-sql", "generic-config", "generic-build", "generic-api",
                "generic-errors", "generic-di", "generic-tests", "generic-dbaccess", "generic-trace", "generic-views",
                "generic-portability", "generic-endpoints", "generic-flows", "generic-areas"]
   ```

   Always add `generic-di` for C# code: it re-applies the calls graphify cannot see (DI dispatch, overrides, messages, events, stored delegates, jobs, redirects, filters) before the other adapters read the graph, so the method map, entry points, test map, database writers and flows all reach further.

   | Adapter | Produces | Needs |
   | --- | --- | --- |
   | `generic-graph` | `components.md` (classes / types, functions: file:line, members, calls into, called by, inherits; **Sets**: number and true / false values a C# class assigns in constructors, initializers and constants, never text), `modules.md` (files), `communities.md`, and the method map `methods.md` (every method's declaration, calls, called by) | graph built |
   | `generic-methods` | only the method map: add it next to `aspnet-mvc-ssdt` | graph built |
   | `generic-deps` | `dependencies.md`: project graph, layers, cycles, every project and package with versions (drift flagged); for .NET packages also the licence, the frameworks the version in use builds for and whether it is Windows-only, read offline from the NuGet packages restored on this machine ("not in local cache" when the solution was never restored here: restore it first for this column) | build manifests, local NuGet package folders |
   | `generic-api` | `endpoints.md`: every HTTP endpoint with verb, route, handler, parameters, declared auth (ASP.NET controllers / minimal APIs / conventional MVC incl. the area prefix from `[Area]` or the `Areas/<Name>/Controllers` folder, Express, NestJS, Flask, FastAPI, Django, Spring, Go, OpenAPI files). Conventional MVC lists **every** public instance method of a controller (MVC routes them whatever they return; static and `[NonAction]` methods are left out), and the auth column is the **effective** auth: method attributes, else the controller or a base controller, else global filters (`GlobalFilters` / `FilterConfig` / `AddMvc` options / `RequireAuthorization`), with the project's own authorisation and authentication attributes found by their base types; the same cell names the **anti-forgery** filter and where it applies (framework filters and the project's own classes named like one, noting when such a class checks the HTTP verb). A **Security review candidates** section (anchor `security-review`, also `docs/agent/api-findings.json`) lists: role attribute on a method that is not an action, admin-looking action without the role attribute its siblings carry, admin-area action without a role filter, state-changing action accepting GET, anonymous state-changing action, no authorisation declared, test or temporary action left routable, helper exposed as action, user-id parameter without the user filter. Options (`adapter_options.generic-api`): `user_filters`, `role_filters` (extra attribute names), `sibling_role_min` (default 2), `test_name_ignore` (regexes of action names that are not test code) | routes in code |
   | `generic-errors` | `errors.md`: every exception, validation, HTTP and database error message with the method that raises it | source |
   | `generic-di` | `dependency-injection.md` (anchors `di-…`): framework features per app, every registration per host application (service, implementation, lifetime, how, key, via module), services → implementations → consumers, constructor dependencies, messages → handlers → senders, request pipeline (middleware, filters, behaviours, hosted services, hubs), background jobs, events / delegates, options bindings, convention scans, wiring findings (missing registration, captive dependency, multiple registrations, service locator), reflection limits; `docs/agent/di.json`. First runs `csharp_resolve.py` (edges into `graph.json`, see [build-code-graph.md](build-code-graph.md)) | C# source; method map for links |
   | `generic-tests` | `test-map.md`: production methods reached by tests through the call graph, the ones nothing reaches, database routines named in tests. Test code is a .NET test project (references a test framework or the test SDK) or a file named like a test that holds a test case: a business feature called "Backtest" is not a test | method map |
   | `generic-dbaccess` | `db-access.md`: for every table and routine, each method that reads, writes or executes it, the operation (from the PARSED statement: insert / update / delete / merge / read / exec, marked when the SQL is built at run time), and the technology (ADO.NET, Dapper, EF Core / EF6 LINQ or raw SQL, NHibernate, JPA, JDBC, Node / Python / Go drivers), following procedure names passed as string literals and name constants | `generic-sql`, method map |
   | `generic-trace` | `ui-map.md`: what each button, link, form or script calls (endpoint → handler → database objects reached); `entry-points.md`: every endpoint, UI event handler and background job with the methods, database objects, errors and flows it reaches, plus "method → entry points", "who changes each table", "where users meet each error", "entry points that reach more than one database" (`cross-db`). Script calls with a joined base URL (`basePath + '/Ctl/Act'`) and `$.ajax({...})` objects with nested braces are read | method map; richer with `generic-api`, `generic-dbaccess`, `generic-errors` |
   | `generic-views` | `views-and-pages.md` (anchors `ui-…`): every view, page, screen and UI component with totals by kind and project (how many screens a user can open; markup and code-behind lines). Covers MVC views / partials / layouts, Razor Pages (with `On…` handlers), Blazor components (routable or not, layouts), Web Forms pages / user controls / master pages, ASMX, ASHX, WinForms forms and user controls (including forms derived from a base form; base forms are not counted as screens), WPF / MAUI XAML windows, pages and user controls. Columns: route (`@page`, or the MVC / Web Forms convention), model / class, layout / master page / base, code-behind, lines, the controller action that renders an MVC view. Web Forms pages, ASMX and ASHX get an auth note from `web.config` (root `<authorization>`, `<location path>`, a sub-folder `web.config`) and code-behind user checks; a **Pages open to anonymous users** section (`ui-anonymous`) lists those with no rule, since global MVC filters never apply to them. An **MVC areas** section lists each area: how it is registered (`Areas/<Name>` folder, MVC 5 `AreaRegistration`, `[Area]` attribute, `MapAreaControllerRoute`, plugin routes with `DataTokens["area"]`, constants resolved), route templates, controllers, actions, views, Razor Pages, screens. `docs/agent/views.json` | .NET UI source; method map and `generic-api` for links (runs late) |
   | `generic-portability` | `platform-portability.md` (anchors `port-…`): what breaks or behaves differently on Linux / modern .NET (Windows-only APIs, System.Web / Web Forms, WCF / ASMX / WPF / WinForms, IIS-bound hosting, APIs removed from .NET, Windows paths and files, Windows time-zone IDs and culture): per rule the severity, why, the suggested fix and every `file:line` with its method; totals per category and project; the Windows-only packages from `generic-deps`. Flags and suggestions only. Uses the **portability categories only** of the migration-assessment rule set (default `linux-readiness`, `web-platform`, `wcf-desktop`, `hosting`, `api-portability`, `file-handling`, `time-culture`; `rules.json`; found in the sibling skill folder, or set `DOCS_ASSESSMENT_RULES` / `adapter_options.generic-portability.rules`; `categories` to change the scope); skipped when that skill is not installed. Same matching as the assessment scan (file types, `requires`, `not`, comments ignored, designer files included). `docs/agent/portability.json` | migration-assessment skill installed; `generic-deps` for packages |
   | `generic-endpoints` | `network-endpoints.md` (anchors `net-…`): **outbound destinations** (host, port, protocol, internal / external / public IP, defined by a URL literal, a host setting such as `Smtp:Host` or `Kafka:BootstrapServers`, a connection string, a WCF client endpoint or a UNC path, and the methods that read the key or hold the literal), **inbound listeners** (launchSettings, Kestrel endpoints, `ASPNETCORE_URLS` / `*_PORTS`, Dockerfile `EXPOSE`, docker-compose ports, `UseUrls` / `Listen` in code, WCF services, IIS-hosted `.svc` / `.asmx`) and **outbound call sites** (HttpClient, WebRequest, RestSharp / Refit, fetch / axios, WCF proxies, SMTP, FTP / SFTP, Redis, RabbitMQ, Kafka, AWS / Azure SDKs, gRPC, SignalR client, LDAP, sockets, MSMQ) with the config keys next to each. Every destination gets a **role** (mail server / SMTP, file transfer / SFTP / FTP, file share / SMB, directory / LDAP, report server / SSRS, ASP.NET session state server, database, cache, message broker, identity provider, logging, payment, object storage, SMS, SOAP / WCF, gRPC, WebSocket, HTTP API) and the place it is configured: appSettings keys (with a sibling `<prefix>Port`), `system.net/mailSettings` `<network host port>`, log4net `smtpHost`, NLog `smtpServer`, `sessionState stateConnectionString` and other `*ConnectionString` attributes anywhere in an XML config. Drive letters other than `C:` in config values and code literals (often mapped network drives) are listed separately. Scheme, host and port only: never paths, query strings or credentials. Copied libraries (`scripts/vendor_files.py`, `graph.vendor_dirs`) are set apart: their URLs go to a **URLs found in third-party code** appendix and their calls are dropped; browser fetch / jQuery calls to a relative URL, `basePath + '/Controller/Action'` or `Url.Action` are counted under **Browser calls to this application**, not as outbound; environment variables named `*_HOST`, `*_ENDPOINT`, `*_URL` … read in code (from `generic-config`) are listed as **Destinations set by environment variables**. Detection is `scripts/network_endpoints.py`, shared with migration-assessment's network allow-list. `docs/agent/network.json` | source and config; method map for links; `generic-config` first for environment variables |
   | `generic-build` | `build-and-run.md`: toolchain, build / test / run commands (solutions with non-SDK-style projects get `nuget restore` + `msbuild`; the test command appears only when the solution has a test project), launch profiles, Docker and compose, CI pipelines, environments, health checks, and **scheduled and background jobs** from `scripts/scheduled_jobs.py` (shared with migration-assessment): hosted services with their interval and config keys, Windows services, Hangfire, Quartz, Azure timer triggers, Spring `@Scheduled`, node-cron, SQL Server Agent jobs, `schtasks` / `Register-ScheduledTask`, Task Scheduler XML, crontab, Kubernetes CronJobs, CI schedules, EventBridge rules, schedule settings and console job projects whose trigger is outside the repository; schedules are decoded to plain words (names and keys only, never values); the evidence for `operations/runbook.md` | build files |
   | `generic-flows` | business-flow pages + interactive viewer from `docs/_src/workflows/flows/*.flow.json` (runs late; see [flows.md](flows.md)) | flow specs (optional) |
   | `generic-sql` | Parsed with Microsoft's T-SQL parser (`scripts/sql_parse.py`; sqlglot fallback), never regular expressions. `db-tables.md` (columns with type / nullability / identity / default / computed / collation, keys, FKs both ways, indexes, checks, temporal / memory-optimized flags, routines that read and write it, PostgreSQL type notes), `db-routines.md` (parameters with direction / default / READONLY, returns incl. OUTPUT / RETURN / result sets, reads, writes with the operation, calls, called by, used by, temp tables, dynamic SQL, PostgreSQL levels; plus types, sequences, synonyms, security policies) and `db-postgres.md` (what converts automatically, needs a rewrite, or has no PostgreSQL equivalent, incl. SQL embedded in code) per database; `agent/db.json`. **Code-only procedures** (`code_only_routines`, default on): stored procedures the code runs by name with no definition in the repository (`scripts/code_routines.py`: command text, name variables / constants, helper methods that run them, Dapper `commandType`, `EXEC` strings) go to `db-code-routines.md` (anchors `sp-<name>`, every call site) and to `db.json` with `"defined": false`, so a repository with no `.sql` still gets a database reference; `code_only_helpers: {"ExecReporting": "Reporting"}` adds helpers and names their database | `.sql` DDL / SSDT; SQL in C# strings; procedure names in code |
   | `generic-config` | `configuration.md`: every config key name per file + code that reads it (never values), and a **Read in code** section (anchors `cfg-code-<key>`): environment variables (`Environment.GetEnvironmentVariable` with its target such as machine, wrappers that pass their parameter to it, `os.environ` / `getenv` / `process.env`) and `AppSettings` / `ConnectionStrings` / `IConfiguration` keys no config file declares, each with the member that reads it; copied libraries are skipped. Option `env_helpers` names more wrappers. A **Credentials written in the source** section (anchor `cfg-credentials`, `docs/agent/source-credentials.json`) lists credential-shaped text in code, config and script files, comments included (Stripe / AWS / Google / GitHub / Slack key shapes, private keys, passwords in connection strings, quoted secret literals): kind, `file:line`, comment or not, tracked by git or not, never the value. `docs/agent/config-reads.json` | config files, source |
   | `generic-areas` | `_src/appendices/code-map.md`: every class / table / routine placed in a business area (narrative, counts for coverage). Areas come from the `rules` option first, then the research areas in `_notes/areas.json` (`use_research_areas`, default true: the most specific area path holding the class file, the routine's definition, or a code-only procedure's first call site), then graph communities / name prefixes | run last |
   | `aspnet-mvc-ssdt` | controllers & actions (verbs, routes, anonymous flags), views, components, models, custom JS, enums, SSDT tables / routines with EF aliases, seed data, SSRS reports, config, NuGet | ASP.NET MVC (+ SSDT) |
   | `custom:<path>` | anything else (routes for Express / Django / Spring, OpenAPI endpoints, GraphQL schema, message contracts …) | see [adapters.md](adapters.md) |

   Use `aspnet-mvc-ssdt` *instead of* `generic-graph` + `generic-sql` + `generic-config` for ASP.NET MVC + SSDT solutions (it is richer and writes its own `configuration.md`); keep `generic-areas`, and add `generic-methods`, `generic-deps`, `generic-build`, `generic-errors`, `generic-di`, `generic-tests`, `generic-dbaccess`, `generic-trace` and `generic-flows` (its own controller pages make `generic-api` optional). Adapters that write the same page overwrite each other: the later one wins.
2. Configure options (`adapter_options`) only where auto-detection is wrong: database folders / page names, EDMX path, web project, seed folder (the `aspnet-mvc-ssdt` options are all auto-detected; see `scripts/adapters/aspnet-mvc-ssdt/_options.py`), area rules (`generic-areas.rules`: `[{"area": "Orders", "regex": "order|invoice"}]`).
3. Set `coverage` to the kinds that must be 100 % discussed in narrative pages (e.g. controllers, classes, routines, tables) and `seed_row_tables` for status / message tables whose rows agents should find one by one.
4. Run `python <skill>/scripts/build_site.py --no-site`. Besides the pages, the build writes the agent toolkit in `docs/agent/`: JSON exports (`methods.json`, `endpoints.json`, `db.json`, `db-access.json`, `errors.json`, `entry-points.json`, `dependencies.json`, `di.json`, `views.json`, `portability.json`, and `stats.json` with each adapter's headline numbers for `[[n:area.key]]` tags in hand-written pages), `entities.jsonl` for `lookup.py`, and `cards.jsonl` (one self-contained retrieval card per method, endpoint, UI trigger, view / page, portability rule, table, routine, error, project, package, flow and narrative section) for a local RAG index. Fix any adapter `FAIL` at the adapter or its options, then rerun.

## Missing a kind of item?

If the stack has something enumerable that no adapter covers (routes, endpoints, events, feature flags, cron jobs, migrations), write a small custom adapter (≈50–150 lines) following the anchor contract in [adapters.md](adapters.md). Rule of thumb: if you would otherwise list more than ~20 items of a kind by hand, write the adapter.
