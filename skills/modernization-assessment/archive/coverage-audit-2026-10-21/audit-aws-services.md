B. AWS Transform for .NET (engines.md, tools-landscape.md)

- HIGH: CLI omitted. AWS announced on 2026-09-09 that AWS Transform for .NET modernization is GA via CLI: an AWS-managed .NET transformation inside AWS Transform custom, run interactively or scripted in pipelines, in 8 regions. Kiro Power is also an access point. engines.md prerequisites describes atx as "for AWS Transform custom" only; tools-landscape lists web app, VS extension and MCP only. Sources: https://aws.amazon.com/about-aws/whats-new/2026/09/aws-transform-dotnet-cli ; https://docs.aws.amazon.com/transform/latest/userguide/dotnet.html . File: engines.md (AWS Transform section, prerequisites); tools-landscape.md row.
- HIGH: Size quota absent. .NET is limited to 1,000,000 lines of code per region per month (web and IDE), adjustable. Concurrency: 5 web jobs, 10 VS-extension jobs. Check the estate's total LOC against this. Source: https://docs.aws.amazon.com/transform/latest/userguide/transform-limits.html . File: engines.md.
- HIGH: Pricing absent. The managed .NET transformation includes 50,000 agent minutes per month free; unused minutes do not carry over; the cap is adjustable. $0.035 per agent minute is listed, but the managed rate above the cap is not stated. Examples: ~50k LOC is ~2,800 minutes (~3 h); ~500k LOC is ~25,000 minutes. Source: https://aws.amazon.com/transform/pricing/ . File: engines.md.
- HIGH: The SQL Server to Aurora PostgreSQL agent ("AWS Transform for SQL Server modernization") is missing from the Choosing table and the DB section. It converts schemas, stored procedures, functions and triggers; modifies EF and ADO.NET code and connection strings; data migration via DMS is optional; output goes to a new branch. The full-stack Windows agent (Dec 2025) covers .NET plus SQL Server and deploys to ECS or EC2 Linux. It overlaps the DB porting agent, so the one-engine-per-project rule applies. Sources: https://aws.amazon.com/transform/windows/sql-server/ ; https://aws.amazon.com/about-aws/whats-new/2025/12/aws-transform-ai-agent-full-stack-windows-modernization/ . File: engines.md (Choosing table, DB section); tools-landscape.md.
- MED: engines.md run step 6 says Next Steps includes a "Linux readiness report (CSV in Visual Studio)". The docs' report hierarchy has no Linux readiness report and no CSV. Next Steps is a markdown file of prompts for continuing in AWS Transform or an AI code companion. Treat the CSV claim as unverified. Sources: https://docs.aws.amazon.com/transform/latest/userguide/dotnet-report.html ; https://docs.aws.amazon.com/transform/latest/userguide/dotnet-ide-how.html . File: engines.md.
- MED: Project types. The docs table lists WinForms, WPF, Xamarin, ASMX, WCF and VB.NET as supported, but the FAQ labels WinForms, WPF, Xamarin and VB.NET as preview. Windows services and worker services appear nowhere. engines.md drops the preview labels and does not mention Windows services. Sources: https://docs.aws.amazon.com/transform/latest/userguide/dotnet.html ; https://aws.amazon.com/transform/faq/ . File: engines.md.
- MED: The best-practices page says "The new .NET agent is not yet available in web console" and recommends the IDE for medium-or-higher complexity. engines.md run steps describe the web flow with no qualification. Source: https://docs.aws.amazon.com/transform/latest/userguide/dotnet-bp-before-transform.html . File: engines.md.
